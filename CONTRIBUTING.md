# Contributing to Toolbox

Thanks for your interest. Contributions are welcome – as a proposal: only what
the maintainer merges is adopted. Toolbox is not an open-source project; usage
rights are defined in [`LICENSE`](LICENSE).

## Process

1. **Open an issue** (for larger changes, please do so first) so it is clear
   whether the proposal fits the app.
2. **Fork** and work on your own branch – not directly on `main`.
3. **Open a pull request** against `main`. Small, focused PRs are much faster
   to review than large mixed changes.
4. **Wait for the review.** The maintainer may accept, reject or request
   changes. A PR is a proposal, not a claim to be merged.

Only what the maintainer merges is adopted: a pull request is a proposal, and
merging is done exclusively by the maintainer. Changes to `main` are made only
by accounts with write access – that is, the maintainer.

## What makes a good PR

- The project builds with Xcode (scheme `Toolbox`) without new warnings.
- Existing style and structure are preserved; no unnecessary rewrites.
- No new dependencies without prior agreement.
- App data stays local; no data is sent to third parties.
- English is used for code, comments, commit messages and documentation.

## Rights to submitted contributions

By submitting a pull request (or a patch by other means) you grant the rights
holder of Toolbox an unlimited, irrevocable, worldwide, royalty-free and
transferable right to use, reproduce, modify, distribute and relicense your
contribution – including under terms other than those of this repository.

This means:

- **You keep your copyright.** It is a grant of rights, not an assignment.
- **You confirm** that you hold the rights to your contribution and can grant
  this right effectively – no third-party content, no code snippets copied from
  projects with an incompatible license.
- **Until it is merged** your contribution remains your proposal; the project
  is not obliged to use it.
- For extensive contributions, a signed Contributor License Agreement (CLA) may
  additionally be required.

If you do not agree with this, please do not submit a pull request – an issue
describing the problem still helps.

## What is not allowed

- Taking code from projects whose license does not permit it.
- Using the project's trademarks, names or design for your own publications.
- Publishing or distributing your own builds of the app (see `LICENSE`).

## Security issues

Please do not report them as a public issue, but directly to the maintainer
(github.com/NHoart).
